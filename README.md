# Plain Work

让 AI 说清楚、给有依据的判断，把时间花在用户要的结果上。

**两轮小型对照均未证明任务质量改善，不建议据此广泛安装。** 这是一个公开实验项目，包含社区研究、一段可选工作约定、可预览和撤回的项目级工具，以及完整对照材料。它不训练模型，不改变权限，也不靠删掉必要检查来换取速度。

## 一分钟试用

Python 3.10+，无第三方依赖，无联网、遥测或后台服务。

```sh
python plain_work.py show --language zh
python plain_work.py add --path /path/to/your/project/AGENTS.md
```

先看差异，认可后才写入：

```sh
python plain_work.py add --path /path/to/your/project/AGENTS.md --apply
```

已有指令原样保留；重复运行不重复添加。默认中文，英文用 `--language en`。按所用客户端的指令加载方式开始一次新任务，并确认其实际读到了目标文件。这个工具写文件成功，不等于模型已加载或遵守它。

撤回时先预览，再写入：

```sh
python plain_work.py remove --path /path/to/your/project/AGENTS.md
python plain_work.py remove --path /path/to/your/project/AGENTS.md --apply
```

只移除本工具原样写入的片段，保留其他内容及后来新增的规则。被手动改动的片段留给你审核，不强行覆盖。原始字节备份保存在目标目录的 `.plain-work-backups/`；它可能包含私人指令，**请加入目标项目的忽略规则，不要公开提交**。工具不扫描其他指令，不修改全局设置，不自动装 skill 或 hook。请不要与其他编辑进程同时修改同一文件。撤回新创建的文件会留下空文件，不会删除它。

升级前，先用安装时的版本撤回旧片段；新版若调整了片段文字，不一定能自动移除旧版。也可以自行审阅并删除两条 plain-work 标记及其间内容，不要删除其他指令。

## 为什么这样做

问题常常同时发生：

- 文字堆砌：用抽象名词替代具体事情，用户需要再翻译一遍。
- 判断缺失：列完所有可能性仍把选择交还用户。
- 工作偏离：反复规划、审查、测试和扩展范围，原本的小任务迟迟没有交付。

所以约定同时处理表达、决策和行动，而不是只要求“简洁”。例如：

- 信息够用时选一个方案，给最关键理由；信息不够时指出哪项未知会改变行动。
- 修正文档错字时做对应检查；改租户权限时做跨租户失败用例，不能借“少测试”省掉它。
- 满足要求后交付，不把重复运行和额外文档当进展。

这些是可检验的设计假设，不是对模型训练动机的诊断。更短不一定更好，敢判断也不等于说得肯定。指令太多或彼此冲突时，继续加规则可能让情况更差；先试一个项目，不要叠加多个类似层。

## 试验与当前证据

见 [pilot-001 的预先固定方案](experiments/pilot-001/protocol.md)及[完整结果](experiments/pilot-001/RESULTS.md)。**本次未测出质量提升：八题全部平局，两组代码任务均通过，候选回答总字符数反而增加 11.8%。** 它包含八个原始合成问答题和一个真实代码修改任务，覆盖明确建议、简单修改、术语解释，以及必须保留不确定性、授权和安全检查的反例。

两组使用相同任务，一组增加本项目约定。答案逐题随机交换 A/B 后再审阅。完整答案、失败、平局和局限都应保留。一次 worker 会话中的八题不是八次独立重复；不能据此宣称某模型普遍更好、节省了多少 token，或解决了代理执行的所有问题。

[第二轮](experiments/pilot-002/RESULTS.md)采用社区报告启发的原创多步骤代码任务，要求新增 CSV 导出并修复租户权限 bug。两组最终实现相同，各通过 11 项隐藏验收及 12 项单测。没有观察到实质交付差距，少一次修复前测试不能当成效率胜利。

准备自己的盲评材料：

```sh
python pilot.py --cases experiments/pilot-001/cases.json \
  --first /path/to/baseline.json --second /path/to/candidate.json \
  --output experiments/local/review-001
```

先创建 `experiments/local`，输出目录必须不存在。答案格式是包含 `id` 和 `answer` 的 JSON 数组，必须完整覆盖题组。只把 `blind.json` 和提前定好的评分标准交给审阅者；评分后再打开 `key.json`。`lengths.json` 只统计字符，不冒充 token、耗时、价格或质量。

## 适用边界

优先在有明确交付物的问答和开发任务试用。若用户要完整研究、风险较高、仓库明确要求全量检查，依任务做足。它不能覆盖系统规则、改变平台确认流程、替你授予权限、修复模型能力缺陷或保证长期记住指令。

问题分析与多社区证据见 [RESEARCH.md](RESEARCH.md)；各类接入方式、官方来源和既有相关项目见 [INTEGRATIONS.md](INTEGRATIONS.md)。当前版本没有经验证的原生 hook/plugin，也未声称在所有 Codex 客户端测试过。
